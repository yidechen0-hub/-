## 常用

### 1. git commit --amend

`git commit --amend` 是 Git 中用于**修改最近一次提交**的命令，常用于修正提交信息或补充提交内容，而不需要创建新的提交记录。

**核心作用**

当你提交后发现：

- 提交信息写错了（如拼写错误、描述不准确）
- 漏提交了文件（忘记 `git add` 某些修改）
- 需要修改最近一次提交的内容

此时可以用 `git commit --amend` 直接修改最近一次提交，而不是新增一个 “修正提交”，让提交历史更整洁。

### 2. 合并多笔提交

在 Git 中，合并多笔提交（也称 “压缩提交” 或 “变基”）可以让提交历史更简洁清晰，常用的方法是通过 `git rebase -i`（交互式变基）实现。以下是详细步骤：

**核心思路**

使用 `git rebase -i` 可以交互式地修改、合并、删除连续的提交记录，通常用于将多个 “临时提交” 或 “修复提交” 合并成一个有意义的完整提交。

**操作步骤（以合并最近 3 笔提交为例）**

**1. 确定要合并的提交范围**

假设最近 3 笔提交需要合并，先通过 `git log` 查看提交历史：

~~~bash
git log --oneline  # 简洁显示提交记录
# 输出示例（最新的提交在最上面）：
# a1b2c3d (HEAD -> main) 修复登录按钮样式
# d4e5f6g 完善表单验证逻辑
# 7h8i9j0 添加用户登录表单
# ...（更早的提交）
~~~

**2. 启动交互式变基**

执行以下命令，指定要合并的提交的**上一个提交**作为基准（即从哪个提交开始修改）：

~~~bash
git rebase -i HEAD~3  # HEAD~3 表示“当前提交往前数 3 个提交”
~~~

- `HEAD~n` 表示 “最近 n 个提交”，n 替换为你要合并的提交数量。
- 也可以直接指定某个提交的哈希值（如 `git rebase -i 7h8i9j0`，合并该提交之后的所有提交）。

**3. 编辑提交指令**

执行命令后，会打开编辑器（如 Vim），显示类似以下内容：

~~~plaintext
pick 7h8i9j0 添加用户登录表单
pick d4e5f6g 完善表单验证逻辑
pick a1b2c3d 修复登录按钮样式

# 指令说明：
# p, pick = 使用该提交
# r, reword = 使用该提交，但修改提交信息
# e, edit = 使用该提交，暂停以便修改内容
# s, squash = 使用该提交，但合并到前一个提交
# f, fixup = 类似 squash，但丢弃该提交的信息
# x, exec = 执行命令
~~~

**关键操作**：

- 保留第一行的 `pick`（作为合并后的主提交）。
- 将后续提交的 `pick` 改为 `s`（或 `squash`），表示 “合并到前一个提交”。

修改后示例：

~~~plaintext
pick 7h8i9j0 添加用户登录表单
s d4e5f6g 完善表单验证逻辑
s a1b2c3d 修复登录按钮样式
~~~

**4. 合并提交信息**

接下来会打开第二个编辑器，让你编辑合并后的提交信息。默认会显示所有被合并的提交信息，你可以删除冗余内容，保留核心描述：
~~~plaintext
# 请输入提交信息（以 # 开头的行将被忽略）
# 合并后的提交信息示例：
添加用户登录功能（包含表单、验证和样式修复）

# 原始提交信息（可删除）：
# 添加用户登录表单
# 完善表单验证逻辑
# 修复登录按钮样式
~~~

保存退出后，Git 会完成合并操作。
